# Reusable Review Decisions

Every release is checked; unchanged confirmed findings do not require another question. This is repository-scoped operational state, not user memory or publishing authorization.

## Workflow

1. Run publish-check from the target repository with `--visibility=private` or `--visibility=public`, after verifying the intended visibility. Omission disables reuse.
2. Read `reviewDecisions.scope` and each finding's `reviewId` from the fresh report. Reused items are INFO, remain visible in the report, and must not trigger a new question.
3. Group only new/changed findings into a concise user question. Do not infer consent from a successful earlier push. Existing explicit conversation approvals can be used only if their exact content and scope match the current finding.
4. After explicit confirmation, the Agent writes/merges a local receipt under the target repository's Git common directory, resolved with `git rev-parse --git-common-dir`: `publisher-review-decisions.json`. Preserve unrelated decisions. Never place receipts or quoted user conversations in tracked repository files.
5. Rerun the check. Only unchanged keep decisions are reusable. Rewrite/remove decisions require actual authorized edits and a fresh scan; they are not warning suppressions.
6. Let the user view recorded decisions on request. Revoke by setting `revoked: true`. Never silently reset or delete receipts.

## Receipt Schema

```json
{
  "schemaVersion": 1,
  "scope": "copy from current report",
  "decisions": [
    {
      "reviewId": "copy the exact finding ID",
      "decision": "keep",
      "confirmedAt": "2026-09-26T00:00:00Z",
      "userQuote": "Exact explicit approval, not an inferred paraphrase",
      "evidenceRef": "Conversation/turn reference for that approval",
      "revoked": false
    }
  ]
}
```

The example timestamp is illustrative: use the actual confirmation time. Do not populate a receipt simply because a user requested this feature. The checker reads receipts but never writes approvals itself. Do not manually change IDs to suppress warnings.

## Matching and Invalidation

- Scope binds the real local checkout, origin URL and requested visibility. Different repository, moved/cloned checkout, changed remote, or private/public transition requires scoped re-confirmation; do not auto-import another machine's receipt.
- File finding IDs include category, file path and matching evidence lines, not whole-file hashes. Unrelated edits do not re-prompt. Changed attribution/identity evidence does.
- Git findings compare unique author/email/signature-status tuples within the checker history window, not commit hashes/counts. More commits by the same identities/status do not re-prompt; new identities/status do.
- Missing, malformed, unsupported, revoked or incomplete receipts do not approve findings. This is local trust state, not cryptographic proof of user consent. The Agent must verify quoted evidence.
- Secrets, unsafe files, compatibility failures, destructive actions and publication authority cannot be approved through this mechanism.
- A workflow requirement such as “图片必须由生图工具生成” is not an author watermark. Explicit credits such as “Generated by Example” or “制作方：某工作室” still require review.

## Reporting

Summarize reused decisions and only the changed items needing input. Do not re-ask a blanket identity question. Never equate an INFO receipt with release authorization or a legal license grant. Respect a current request to postpone publication even when all checks pass.
